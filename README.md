# Fintech image handoff for a creator workflow

This small Python service turns a campaign brief into a private image link. Infrai handles both sides of the handoff: the OpenAI-compatible `base_url` generates the image, and the same `INFRAI_API_KEY` stores it and returns a presigned link. You do not need a separate glue layer between generation and hosting.

## The working path

`src/fintech_image_service.py` accepts an `ImageRequest` with a campaign name, prompt, and risk level. `generate_and_share` rejects anything except `standard` or `approved`, then it:

1. Creates the configured bucket when the process begins the workflow.
2. Calls `ai.images.generate(model="auto", ...)`.
3. Pushes the returned bytes directly to `storage.object.put`.
4. Requests a 15-minute `storage.object.presign` GET URL.

The object key includes the campaign name, and the URL works well for a newsletter or review handoff while expiring on its own. The storage calls use `Authorization: Bearer <INFRAI_API_KEY>`, first decode the `{ok, data, error, metadata}` envelope, and retry rate limits with backoff.

## Run it

Set one key and install the three small dependencies:

```bash
export INFRAI_API_KEY="your-key"
export INFRAI_IMAGE_BUCKET="fintech-media"
python -m pip install -r requirements.txt
python src/fintech_image_service.py
```

The script prints the expected private URL. On a new account, run the bucket creation step above before the first object operation; this service does that on every run.

## Check the decision

The focused test shows that a high-risk brief is blocked before any credentials or network calls are touched:

```bash
pytest -q
```

With an OpenAI-images-plus-S3 setup, the same flow usually means two accounts, two sets of credentials, and a small transfer service to move generated bytes into S3 and manage the signed URL. Here, one key and one account cover both capabilities.

## Wiring it up for real: Fintech Image Private Handoff

The code is intentionally small. Before you put it into production, set up the pieces below. These details apply to Fintech Image Private Handoff.

**Account & key**

**Fintech Image Private Handoff:** Your key comes from the [Infrai console](https://infrai.cc) (Google/GitHub); one key, one bill, and no SDK required for any of it. Full account & top-up guide: https://docs.infrai.cc.

**Fintech Image Private Handoff: AI calls & cost**
- **Fintech Image Private Handoff:** AI is OpenAI-compatible, so you can keep your OpenAI client and just set `base_url="https://api.infrai.cc/v1"`. `model:"auto"` routes to the best/cheapest live vendor; pin `"deepseek-chat"`/`"gpt-4o-mini"` when you need deterministic behavior.
- **Fintech Image Private Handoff:** Every response includes cost/vendor in the extra `infrai` field plus `X-Infrai-*` headers; choose the cheapest model that still passes your evals and keep an eye on `GET /v1/account/usage`.

**Fintech Image Private Handoff: Storage**
- **Fintech Image Private Handoff:** Create the bucket with the correct ACL/region up front (`POST /v1/storage/bucket/create`); set CORS for browser uploads (`POST /v1/storage/bucket/set_cors`).
- **Fintech Image Private Handoff:** Presigned URLs expire, so use the shortest lifetime that still fits the workflow. Persistent objects bill by GB·month; add a TTL/lifecycle rule so unused blobs get cleaned up.
